# تجهيز تسجيل الأسر — محلي فقط

أُضيف مسار مستقل لتسجيل ولي الأمر وإدارة ملفات الأطفال بالعربية والإنجليزية. هذا تجهيز برمجي قابل للاختبار، **وليس إطلاقًا عامًا**. نجح فحص اتصال مستضاف للقراءة فقط؛ لم تُختبر رحلة إنشاء الحساب والبريد والدخول المستضافة. وافق المالك على commit وpush إلى `preview/academy-synthetic` فقط، لتشغيل ربط Vercel الحالي تلقائيًا. التسجيل يظل مغلقًا في المعاينة، ولا يُغيّر `main` أو الإنتاج أو أي إعداد خارجي.

## ما أُضيف

- صفحتا `/ar/family` و`/en/family`، بلا رابط تسجيل عام جديد، وبـ`noindex`.
- API منفصل `/api/family`: إنشاء حساب ولي أمر، اشتراط تأكيد البريد، دخول وخروج، استكمال ملف الولي بالموافقة، وإضافة ملفات الأطفال وتعديلها وحذفها.
- محوّل خادمي لـSupabase Auth وPostgREST مثبت على المشروع `vbulxdnfknoybdkuhayz`. لا يستعمل كلمة مرور قاعدة البيانات أو مفتاح service_role.
- مخطط `db/family-registration.sql` لجدولي `academy_guardians` و`academy_children`، مع عزل RLS وعلاقة ملكية ثابتة. يُلغي منح الأدوار الافتراضية الزائدة، بما فيها TRUNCATE الذي لا تحميه RLS، قبل منح الصلاحيات الضرورية.
- الطفل ملف تحت ولي الأمر، بلا بريد أو كلمة مرور أو تسجيل دخول أو اختيار دور. لا حساب معلم أو إدارة عبر هذا المسار.

## حدود الأمان والتشغيل

التسجيل مغلق افتراضيًا. حتى مع `ACADEMY_FAMILY_REGISTRATION=local-review` يقبل فقط مضيف loopback وأصل الطلب نفسه، ويرفض بيئات Vercel المعاينة والإنتاج وغيرها من أعلام الاستضافة المعروفة. أوامر خادم المشروع ترتبط بـ`127.0.0.1`. لا تنشر منفذ المراجعة عبر نفق أو proxy، ولا تضف مفاتيح إلى المعاينة الاصطناعية.

تُراجع هوية الجلسة عبر Auth `/user`، لا دور مرسل من المتصفح ولا هوية العرض التجريبي. يُحفظ access token فقط في cookie محصور بمسار API وHttpOnly/SameSite=Strict ولمدة أقصاها ساعة؛ لا يُحفظ refresh token ولا يُستخدم localStorage أو sessionStorage. يلزم تسجيل الدخول مجددًا بعد انتهاء الجلسة. عدم استخدام Secure مقصور على HTTP المحلي؛ هذه ليست إعدادات نشر إنتاجية.

إنشاء الحساب لا يفتح جلسة في الواجهة. بعد تأكيد البريد والدخول، يُطلب استكمال اسم الولي واللغة وإقرار التفويض، ويُسجل إصدار الموافقة ووقتها خادميًا. اسم الولي وإقرار الواجهة قبل إنشاء الحساب لا يُرسلان إلى metadata ولا يُستخدمان لمنح أدوار. قبل التشغيل الفعلي يلزم اعتماد نص الموافقة والسياسات، لا اعتبار هذه الصياغة اعتمادًا قانونيًا.

حد محاولات الدخول الحالي داخل عملية واحدة للمراجعة المحلية فقط، وليس حماية إساءة استخدام إنتاجية. استرجاع كلمة المرور، إدارة الجلسات المتقدمة، حذف الحساب وتصدير البيانات وسياسة الاحتفاظ تحتاج استكمالًا قبل إطلاق عام.

## ما لم يتغير

مساحة الدروس السابقة `/workspace` تبقى اصطناعية: **ملفات الأسرة الجديدة لم تُربط بعد بسجلات الدروس والخطط والتقارير الحقيقية**. لا تسجيل طالب بالغ جديد ضمن هذه الدفعة. الحصص فردية كما هي؛ لا تحصيل حقيقي، ولا تفعيل اشتراك مالي أو Zoom أو استيراد مواد قرآن/تجويد/نور البيان. يستخدم المعلم مواده بنفسه داخل Zoom مستقبلًا بعد اعتماد الربط، دون إدارة تلك المواد هنا.

لم تُستخدم أسرار Zoom، ولم تُنشأ حسابات حقيقية أو تُرسل رسائل بريد. طُبق migration `family_registration` في المرحلة السابقة المأذون بها، بعد التحقق من خلو public والمهاجرات من التعارضات. وُثق وجود الجدولين مع RLS مفعّل وإجباري و4 سياسات ملكية لكل جدول و0 صف. لم يُنفذ DDL بعيد إضافي في هذه الدفعة، ولم تتغير إعدادات Auth أو GitHub أو Vercel.

## الاختبار المحلي دون أي بيانات اعتماد

```bash
npm run typecheck
npm run lint
npm run build
npm run test:family
npm run test:family:browser
npm run test:academy
npm run test:phase2:hardening
npm run test:preview
```

`test:family` يجمع اختبارات المحوّل وHTTP بمحاكاة fetch دون شبكة، واختبارات PostgreSQL 16 فعلية داخل cluster اصطناعي مؤقت منفصل يُنشأ ويُحذف تلقائيًا. لا يقبل هذا المشغل عنوان قاعدة مستضافة.

`test:family:browser` يشغل خادمين محليين على3420 و3421 دون أي مفتاح. اختبارات UI تحاكي API ببيانات اصطناعية؛ تثبت رحلة الواجهة لا اتصال Supabase. تختبر أيضًا الإغلاق الفعلي وCSRF وعدم ظهور النماذج في وضع الاستضافة. أصلحت هذه الدفعة اختبار الصفحات بلا JavaScript لاستخدام baseURL بدل تثبيت منفذ3000، لذلك يعمل مع معاينة3410.

## نتائج التحقق لهذه الدفعة

- `npm run typecheck` و`npm run lint` و`npm run build`: نجحت جميعها، exit code 0.
- `npm run test:family`: نجحت 18 حالة للمحوّل وHTTP، و8 حالات PostgreSQL محلية معزولة، دون فشل أو تخطٍ.
- `npm run test:academy`: نجحت 15 حالة؛ `npm run test:phase2:hardening`: نجحت 34 + 6 حالات.
- `npm run test:family:browser && npm run test:preview`: اكتمل الأمران بنجاح، exit code 0؛ اختبارات المعاينة السابقة 92/92. اختبارات واجهة الأسرة اصطناعية بلا مفتاح أو إنشاء حساب بعيد.
- `check:family:connection`: نجحت القراءات الثلاث على المشروع الحقيقي بالمفتاح المحفوظ في بيئة العملية فقط.
- فحص HTTP محلي بالمفتاح الحقيقي: صفحتا العربية والإنجليزية 200 مع noindex ودون المفتاح في HTML؛ API يعيد حالة غير مصادق عليها دون cookie وبـno-store، ويرفض أصلًا مخالفًا بـ403. لم تُنفذ POST وأُوقف الخادم بعد الفحص.
- فحوص CLI: غياب المفتاح يفشل بـ`configuration_required`، وبيئة الاستضافة بـ`registration_disabled`، والوسائط غير المسموحة تُرفض. `git diff --check` ناجح.
- فحص 1070 ملفًا في المشروع ونتائج البناء (مع استثناء `.git` و`node_modules`) لم يجد قيمة المفتاح. لم يُنشأ ملف `.env` فعلي.

## الربط المحلي بالمشروع الحقيقي — ليس إذن إطلاق

أُضيف `scripts/family-review.ts` وأمرا `npm run check:family:connection` و`npm run dev:family`. يتلقى المشغل المفتاح المحفوظ عبر متغير البيئة `ACADEMY_SUPABASE_PUBLISHABLE_KEY` فقط، ولا يكتبه في الملفات ولا يطبعه. يثبت عنوان المشروع المحدد، ويرفض المفاتيح السرية/service_role وبيئات الاستضافة. لا تحتاج البناء والاختبارات الاصطناعية إلى المفتاح، ولا يُمرر لها.

الفحص ينفذ ثلاث قراءات GET ثابتة فقط: إعدادات Auth، وقراءة `id` بحد `limit=0` لكل جدول دون جلسة. نجح الفحص الفعلي: `mailer_autoconfirm=false`، `disable_signup=false`، `external.email=true`، ورفض الجدولين للزائر بخطأ الصلاحيات `42501`. هذه القراءات لا تنشئ حسابًا أو رسالة أو صفًا، ولا تثبت عزل حسابات مصادقة متعددة أو تسليم البريد أو صحة Site URL.

أمر `dev:family` يجري الفحص نفسه أولًا، ثم يشغل Next على `127.0.0.1:3430` فقط. صفحتا المراجعة: `/ar/family` و`/en/family`. **التسجيل من الواجهة المتصلة سيؤدي إلى إنشاء حساب وإرسال تأكيد؛ لذلك لم يُجرّب ولم يؤذن باستخدامه في هذه الدفعة.** لا تشغل نفقًا أو forwarding ولا تدخل بيانات أسر حقيقية. تسجيل الدخول ينشئ cookie محلية فقط ولا يربط مساحة الدروس الاصطناعية بالمستخدم الحقيقي تلقائيًا.

لم تعد إتاحة المفتاح أو تطبيق المخطط عائقين. المتبقي قبل اعتماد التشغيل:

1. توجد موافقة سابقة على حساب اختبار واحد ورسالة تأكيد واحدة للمالك، لكنها لا تسمح بتنفيذهما قبل حل مسار التأكيد بأمان، ولا تشمل اختبار حسابين أو تغيير Auth أو SMTP. لم يُنشأ أي حساب ولم يُرسل بريد، ولا تُنفذ أي منهما ضمن رفع المعاينة.
2. Site URL الحالي هو `http://localhost:3000` ولا يوجد callback مكتمل. يلزم اعتماد منفصل لأي تعديل خارجي لحل مسار التأكيد، ثم التحقق من التسليم. نجاح `/settings` يثبت تفعيل مزود البريد واشتراط التأكيد فقط؛ لا يثبت وصول رسالة. لا يوجد callback جديد ولا استعادة كلمة مرور في هذه الدفعة.
3. استكمال ربط التعليم بمصادقة حقيقية، واعتماد الخصوصية والموافقة والاحتفاظ والحذف والاسترجاع وحماية الإساءة وHTTPS/cookies الإنتاجية.
4. **موافقة مستقلة وصريحة من المالك قبل الإطلاق العام**، تشمل النطاق والبيئة والإعدادات. لا يوجد علم إعداد يسمح بالإطلاق العام؛ يحتاج ذلك تغييرًا مراجعًا منفصلًا. الإذن الحالي يقتصر على رفع فرع المعاينة، دون force-push أو تعديل `main` أو إعدادات Vercel وSupabase.

مرجع المصادقة: [توثيق Supabase الرسمي للتسجيل والجلسات وتأكيد البريد](https://supabase.com/docs/reference/javascript/auth-signup). قواعده تدعم إبقاء التسجيل دون جلسة عند اشتراط تأكيد البريد، والتحقق الخادمي من المستخدم بدل الثقة في بيانات cookie وحدها.
