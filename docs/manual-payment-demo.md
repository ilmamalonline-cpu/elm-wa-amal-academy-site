# تجربة الدفع من البداية إلى المراجعة

توجد الآن واجهتان عربيتان محليتان: واجهة لولي صناعي ثابت، وأخرى لمراجع صناعي ثابت. التجربة **معطلة افتراضيًا**، وليست تسجيل دخول أو تحصيلًا حقيقيًا. الموقع العام وروابطه وأسعاره لم تتغير. لا يظهر رقم محفظة أو أمر تحويل في الواجهتين.

## تشغيلها

من جذر المشروع، بعد تثبيت الاعتمادات الموجودة:

```bash
NEXT_TELEMETRY_DISABLED=1 npm run build
MANUAL_PAYMENT_DEMO=synthetic-only npm run demo:manual-payment
```

بدون القيمة الدقيقة `synthetic-only` يرفض المشغّل البدء. يطبع رابطين مختلفين على `127.0.0.1`، أحدهما للأسرة والآخر للمراجع. افتحهما على الكمبيوتر نفسه؛ لا تنشرهما ولا تمرر منافذهما إلى الإنترنت. الوصول المحلي إلى أي منهما يمنح هوية **التجربة الثابتة فقط**: هذا فصل للاختبار وليس نظام مصادقة تشغيلية أو حسابًا موثقًا للمالك.

ينشئ المشغّل عنقود PostgreSQL16 مؤقتًا جديدًا وبيانات fixtures فقط، ولا يقبل قاعدة موجودة أو مفتاح توقيع أو حسابًا من متغيرات البيئة. يحتاج إلى الحزمة المستخرجة الموجودة حاليًا تحت `/workspace/phase2-tools/root/usr/`؛ لم ندّع دعم تشغيله على أي جهاز بلا تلك المتطلبات. لا يبدأ Auth/Storage الأصليين ولا يقترب من قاعدة المزوّد المحضّرة.

يوقف Ctrl+C الخوادم ويحذف بيانات التجربة. يتوقف أيضًا بعد 45 دقيقة، قبل انتهاء جلسات fixtures. الإنهاء القسري للعملية أو تعطل الجهاز قد يمنع التنظيف التلقائي؛ لا تستخدم هذا المشغّل لتخزين سجلات دائمة.

## خطوات المراجعة

1. **الأسرة:** أنشئ الطلب الصناعي. تُعرض باقة القرآن وسعرها الأصلي **360 SAR**، وثماني حصص ومدة الحصة وشروط التجربة. لا يوجد مبلغ EGP مشتق من السعر.
2. **المراجع:** حدّث القائمة واختر الطلب. أدخل مبلغ العرض بأصغر وحدة عملة، ثم العملة والطريقة صراحة. مثال مستقل: `36000` و`SAR` و`synthetic-manual-agreement`. لا توجد قيمة مبلغ افتراضية. طريقة `synthetic-egyptian-wallet` مجرد محاكاة تتطلب EGP؛ لا رقم وجهة ولا سعر صرف ولا تحويل فعلي.
3. **الأسرة:** حدّث الطلب واقرأ المبلغ والعملة والطريقة وإصدار العرض. ضع علامة القبول الصريح ثم اضغط قبول العرض. بعد القبول فقط يمكن تقديم مرجع مثل `SYNTHETIC-DEMO-001`. **يبقى الطلب غير مفعّل** بعد تقديمه. رفع الملفات غير متاح.
4. **المراجع:** حدّث الطلب. للرفض، أدخل سببًا واضغط الرفض؛ يظهر السبب للأسرة، ويمكنها تقديم مرجع صناعي جديد بمحاولة مرتبطة بالسابقة. لا تُمحى المحاولات أو تُعدّل.
5. **المراجع:** للموافقة، أدخل سببًا ومبلغًا وعملة مطابقين، ومصدر تحقق مستقلًا صناعيًا مثل `SYNTHETIC-LEDGER-001`. أكّد القدرة على توفير الحصص، ثم الموافقة الصريحة على التفعيل. الخادم الحالي يراجع الصلاحيات والحالة؛ لا يكفي زر أو ادعاء دور من المتصفح.
6. **الأسرة:** بعد الاعتماد فقط يظهر تفعيل صناعي لثماني حصص مع البداية والنهاية ومعرّف التفعيل. الفترة شهر تقويمي بتوقيت القاهرة، دون تجديد تلقائي. لا استهلاك حصص أو جدولة أو إشعارات تعمل.

استخدم معلومات وهمية فقط حتى في حقول السبب والملاحظات؛ الواجهة ليست أداة لإخفاء البيانات الشخصية التي يكتبها المختبر بنفسه.

## ما يحمي المسار

لكل واجهة أصل محلي منفصل وهوية fixtures يحددها الخادم. المفاتيح وBearer تبقى في ذاكرة المشغّل ولا تصل إلى HTML أو JavaScript أو سياق المتصفح. لا يوجد تبديل دور يرسله العميل. الواجهة المحلية تمنع الأوامر المخالفة للشخصية، والخادم وقاعدة البيانات يعيدان فحص الجلسة والصلاحية والولاية المالية عبر المسار القائم دون تعديل حدوده.

طلبات الكتابة تحتاج أصل الواجهة نفسه؛ الطلبات ذات Host مخالف أو ترويسات forwarding أو credentials من المتصفح مرفوضة. لا CORS أو cookies أو تخزين متصفح دائم أو أصول خارجية. الاستجابات `private, no-store` مع سياسة محتوى مقيدة. رفع الملفات معطل. لا تجعل هذه الحواجز مشغّل fixtures صالحًا للإنتاج.

يحتفظ العميل بمعرّفات ثابتة داخل جلسة الصفحة لإعادة الطلب نفسه، وتظل قيود الخادم والمعاملات هي ضمان عدم ازدواج التفعيل حتى بعد إعادة تحميل الصفحة أو مفتاح جديد. إذا تعثرت استجابة فحدّث الحالة أولًا؛ المرجع المكرر أو التناقض يُرفض ولا يُسوّى تلقائيًا.

## الاختبارات

```bash
npm run test:manual-payment:demo
MANUAL_PAYMENT_TEST=synthetic-only npm run test:manual-payment
MANUAL_PAYMENT_TEST=synthetic-only npm run test:manual-payment:http
npm run typecheck
npm run lint
npm run test:phase2:hardening
```

اختبار الواجهة هو تشغيل اختباري صريح ينشئ موارده ويحذفها، ولا يفعّل التجربة في التشغيل العادي. يحتاج البناء الحالي و`/usr/bin/chromium` والمتطلبات المحلية السابقة. النتائج المنفذة فعليًا تُسجّل أدناه عند اكتمالها؛ الأوامر وحدها ليست دليل نجاح.

## ما لم يُحسم للتشغيل الحقيقي

لا تزال ملكية المحفظة وعلامتها غير متحققتين، وهوية المالك ومنح الإدارة وMFA والاسترداد غير منفذة. يلزم اعتماد آلية مبلغ كل طلب وقبوله، وإجراءات التحقق البشري من الوصول، والشروط والخصوصية والحماية والاحتفاظ والنزاعات والتسويات والاسترداد وحالات DST والإساءة والإشعارات. ويلزم حسم مسؤوليات الخدمات والميزانية والدعم وحماية الأطفال والتجربة المراقبة وموافقة الإطلاق (D11).

هذه بوابات تشغيل لاحقة، وليست عائقًا لتجربة البيانات الصناعية. لم تُضف أي خدمة مستضافة أو دفع فعلي أو بيانات حقيقية أو ربط Zoom أو استيراد منهج. لم يتغير مخطط المزوّد أو حد الأمان أو البديل المتقاعد أو محتوى الصفحة العامة. لا migration على قاعدة محضّرة أو حية، ولا commit أو push أو نشر.

## نتائج هذه الإضافة

- **3/3 اختبارات UI/API جديدة ناجحة** على Chromium الفعلي: رفض بدء المشغّل دون opt-in، دورة الأسرة والمراجع على أصلين منفصلين، القبول الصريح ورفض تقديم المرجع قبله أو قبول مبلغ مختلف، عدم التفعيل من المرجع، الموافقة الصريحة مع تأكيد القدرة، إعادة قرار المراجعة بنفس معرّف التفعيل، منع انتحال الشخصية والترويسات ومخالفات الأصل والمسار والاستعلام، منع الملفات، عزل ولي آخر، وعدم تسريب رقم المحفظة أو Bearer. استُخدم عرض هاتف `375×812` للأسرة مع فحص غياب التمرير الأفقي.
- أُعيدت اختبارات الخادم: **19/19** قاعدة بيانات، **10/10** API، و**2/2** HTTP على بناء Next الفعلي. تشمل اختبارات الخادم السابقة الرفض وإعادة التقديم والتزامن وrollback؛ لا ندّعي أن كل ذلك جُرّب بأزرار الواجهة الجديدة.
- نجحت `npm run build` و`npm run typecheck` و`npm run lint` وفحص syntax للملفات الجديدة. أُعيدت اختبارات التحصين/التقاعد offline: **34/34 + 6/6** ناجحة.
- لم تُعد اختبارات المزوّد native أو كامل اختبارات الموقع العام التاريخية، ولم تُثبّت مكتبات جديدة أو تُجرَ مراجعة اعتمادات جديدة. فحص عدم ظهور رقم المحفظة شمل الصفحة العامة `/ar/packages` وأصول التجربة.

السجلات في `docs/checks/manual-payment-demo/`: `ui-tests.log` و`backend-tests.log` و`http-tests.log` و`static-and-hardening.log`. الجرد والبصمات في `change-inventory.json`؛ بصمات ملفات الحدود مرجع للحالة النهائية، وليست ادعاء إنشاء مقارنة بتاريخ غير موجود.
